# La Vague Imports — storefront

Next.js 16 storefront for La Vague Imports, a specialty food importer in Little
Ferry, NJ serving New York and New Jersey.

The site is a **catalog + quote-request** storefront: customers build a list of
products and submit it as a quote request. No payment is taken online. Wholesale
runs on an application form — approved accounts are quoted manually.

## Stack

| Layer      | Choice                                                |
| ---------- | ----------------------------------------------------- |
| Framework  | Next.js 16 (App Router, Turbopack, React 19)          |
| Language   | TypeScript                                            |
| Styling    | Tailwind CSS v4, olive/white brand theme in `globals.css` |
| Database   | PostgreSQL via Prisma 7 (`prisma-client` generator + `@prisma/adapter-pg`) |
| Validation | Zod 4, inside React server actions                    |
| Icons      | lucide-react                                          |

## Running it

```bash
npm install
npm run dev
```

The storefront runs **without a database**. Catalog reads fall back to the seed
catalog in `src/lib/catalog/data.ts`, so every page renders immediately. Only
the three write paths (quote requests, wholesale applications, contact
messages) need Postgres — without it they show a "call us instead" message and
log the full submission to the server console.

### Connecting Postgres

Pick one, then put the connection string in `.env` as `DATABASE_URL`:

- **Docker** — `npm run db:up` (uses the included `docker-compose.yml`), then
  `DATABASE_URL="postgresql://lavague:lavague@localhost:5432/lavague?schema=public"`
- **Existing local Postgres** — create a database and user, then point at it.
- **Hosted** — `npx create-db` (Prisma Postgres), Neon, Supabase, or Railway.

Then:

```bash
npm run db:migrate
npm run db:seed
```

`db:seed` loads the same catalog from `src/lib/catalog/data.ts`, so the DB and
the fallback never drift. It is idempotent — safe to re-run.

Useful: `npm run db:studio` opens Prisma Studio to read incoming quote requests
and wholesale applications.

## Updating the catalog

The catalog is generated by merging several sources into one file
(`src/lib/catalog/catalog.json`), never hand-edited. Each importer writes its own
`catalog.<source>.json`; `build-catalog.mjs` merges them.

| Source | Site | Platform | Importer |
| --- | --- | --- | --- |
| La Vague | (Wix export CSV) | Wix | `import-wix-catalog.mjs` |
| halalco | halalco.com | Shopify (`products.json`) | `import-halalco.mjs` |
| Ziyad | ziyad.com | WooCommerce (Store API) | `import-ziyad.mjs` |
| Fattal's | fattals.com | BigCommerce (sitemap + JSON-LD) | `import-fattals.mjs` |
| Moroccan Olive Grove | moroccanolivegrove.com | Shopify | `import-mog.mjs` |

Regenerate the whole catalog:

```bash
# Re-pull each source (network; skip any you don't need to refresh):
node scripts/import-wix-catalog.mjs      # reads data-import/wix-catalog.csv
node scripts/import-halalco.mjs
node scripts/import-ziyad.mjs
node scripts/import-fattals.mjs
node scripts/import-mog.mjs
# Merge them all into catalog.json:
node scripts/build-catalog.mjs
# Push to the database:
npm run db:seed
```

`build-catalog.mjs` merges every `catalog.*.json`, **dedupes by exact product
name** (keeping the priced record and unioning collections), re-categorizes
everything into ~19 unified grocery categories (`CATEGORIES` + `ALIASES` in that
file), and rebuilds the shop's collection filters. A `0`/absent price becomes
**"price on request"**. Image hosts for every source are allow-listed in
`next.config.ts`.

Dedup is intentionally exact-name only: the merge keeps one record and drops the
other, so collapsing near-matches (e.g. different sizes of one product) would lose
data. Same-product-different-size is the job of variation grouping, not dedup.

### Notable decisions

- **Prices are integer cents, and nullable.** `null` means "price on request" —
  most wholesale lines are quoted, not listed. `formatPriceOrRequest` renders the
  label; the quote flow, cart, and totals all handle null prices.
- **Products carry a primary `category` plus raw `collections[]`.** The category
  drives the nav; the collections drive the shop's filter dropdown. The importer
  assigns the primary category from the collections.
- **Quotes are re-priced server-side.** The browser's cart is treated as
  untrusted input; `submitQuoteRequest` looks up authoritative prices by variant
  id before writing anything.
- **The quote list is a `localStorage`-backed external store** read through
  `useSyncExternalStore`, so the server render and the hydrated client render
  agree, and the list syncs across tabs.
- **`src/lib/catalog/index.ts` is `server-only`.** Client components import
  types from `src/lib/catalog/types.ts` instead.
- **`Store` and `DeliveryZone` are modelled but unused.** They're in the schema
  now so the future multi-store delivery rollout doesn't need a destructive
  migration.

## Content still to replace

The catalog is now real (imported from Wix). Remaining items to correct before
launch:

1. **Product images point at the Wix CDN.** 516 of 652 products reuse their
   `static.wixstatic.com` image URLs; the other ~136 show a branded placeholder.
   This works, but the images live on Wix — to fully leave Wix, re-host them and
   update `imageUrl` (or add local files and adjust the importer).
2. **The logo.** The header wordmark is set in Playfair Display next to an SVG
   olive mark. To use the supplied artwork, replace the markup in
   `src/components/brand/logo.tsx` with an `<Image src="/logo.png" …>`.
3. **Case packs and minimums.** The Wix export had no pack sizes, so
   `unitsPerCase` / `minOrderCases` are null and the line sheet shows "—".
   Populate them if you want case packs on the wholesale line sheet.
4. **Wholesale terms.** The minimum order, delivery threshold, lead time, and
   Net 15 terms on `/wholesale` are placeholders in `src/app/wholesale/page.tsx`.
5. **Ribbons and categories.** Ribbons come straight from Wix ("HOT ITEM",
   "DHL EXPRESS", etc.) — prune any you don't want. The category mapping lives in
   `scripts/import-wix-catalog.mjs` (`CURATED`); ~71 products landed in
   "Specialty & Other" because their collections didn't map elsewhere.
